# 🔥 شعله باشی (Sholeh Bashi)

اپلیکیشن اندروید برای **پیشنهاد غذا و دستور پخت**. کاربر سلیقه، رژیم و شرایطش را مشخص می‌کند و اپ سه غذای مناسب پیشنهاد می‌دهد. حس اپ باید «وارد شدن به آشپزخانه» باشد: گرم، زیبا، روان و سبک.

> این فایل برای همه‌ی کسانی است که وارد پروژه می‌شوند: اول بخوانید اپ چیست، بعد بخش «چطور ادامه بدهیم» را ببینید.

---

## ۱. اهداف و اصول

| اصل | معنی در عمل |
|---|---|
| مصرف باتری حداقل، بدون گرم شدن گوشی | هیچ سرویس پس‌زمینه یا Polling نیست. API فقط با اقدام کاربر صدا زده می‌شود. انیمیشن‌ها سبک‌اند. |
| زیبایی و حس آشپزخانه | پالت گرم، انیمیشن روان بین صفحه‌ها، Lottie سبک. |
| ریسپانسیو | Jetpack Compose + Material 3؛ باید روی اندازه‌های مختلف گوشی تست شود. |
| Local-first | دیتابیس روی گوشی (Room). اپ بدون اینترنت هم غذاهای خودی را نشان می‌دهد. |
| امنیت کلید API | کلید Gemini و Grok **هرگز** داخل APK نمی‌ماند؛ فقط روی سرور واسط است. |
| انتشار محدود | فعلاً فقط روی چند گوشی؛ دسترسی API با شناسه‌ی دستگاه کنترل می‌شود. |

---

## ۲. تکنولوژی‌ها

- **Kotlin + Jetpack Compose** (Material 3)، حداقل SDK ۲۴
- **Room** برای دیتابیس لوکال، **DataStore** برای تنظیمات
- **Retrofit + kotlinx.serialization** برای ارتباط با سرور واسط
- **Navigation Compose** با انیمیشن انتقال
- **Lottie** (انیمیشن سبک)، **Coil** (عکس)
- **KSP** برای پردازش Annotation
- **سرور واسط** (Cloudflare Workers، خارج از ایران) که به Gemini و Grok وصل می‌شود

## ۳. صفحه‌ها و ویژگی‌ها

### دیالوگ خوش‌آمد
در اولین ورود، پنجره‌ای خوش‌آمد می‌گوید و کار اپ را توضیح می‌دهد. گزینه‌ی «بستن» و «دیگر نشان نده» دارد (ذخیره در DataStore با کلید `hide_welcome`).

### صفحه‌ی اصلی (۵ گزینه)

**۱. غذای رندوم**
- یک غذا به‌صورت تصادفی از دیتابیس نشان می‌دهد.
- دیتابیس شامل **۵۰۰ غذای سازنده** (در ۱۰ فایل seed) و غذاهای اضافه‌شده توسط کاربر است.
- کاربر می‌تواند غذا اضافه کند.
- نشان‌گذاری: «محبوب» و «برای پختن در آینده».

**۲. غذای جدید (با API)**
کاربر خواسته‌اش را مشخص می‌کند، سپس **سه غذا** پیشنهاد می‌شود. گزینه‌ها:
1. **می‌خواهم داشته باشد** (مثلاً برنج): کاربر دستی می‌نویسد. موارد ثبت‌شده در دیتابیس ذخیره می‌شوند و دفعه‌ی بعد زیر کادر نوشتن به‌صورت پیشنهاد (Suggest) می‌آیند.
2. **نمی‌خواهم داشته باشد** (مثلاً خیار): دقیقاً مثل گزینه‌ی ۱.
3. **المان‌های مهم**:
   - بدنسازی (افزایش حجم)
   - کاهش وزن
   - حساسیت‌ها (ثبت، Suggest و حذف مثل بالا)
   - رژیم خاص (کاربر می‌نویسد)
4. **دلت چی می‌خواد؟** توضیح تکمیلی آزاد.
5. **تعیین وعده:** صبحانه، ناهار، شام، عصرانه، دسر، سالاد و ...
6. **کشور/منطقه:** ایران، عربی، ترکی، شرق آسیا، بقیه‌ی آسیا، اروپا، قاره‌ی آمریکا، آفریقا.

خروجی: سه غذا، با قابلیت نشان‌گذاری (محبوب / آینده).

**۳. غذاهای قبلی:** غذاهایی که کاربر تایید کرده است.

**۴. نشان‌شده‌ها:** هم «پسند شده‌ها» و هم «برای آینده».

**۵. درباره‌ی ما:** معرفی اپ، نسخه، و آیدی تلگرام سازنده.

### جدول‌های Room

- `recipes`: غذاها (`source` = `builtin` | `remote` | `user` | `ai`)
- `meal_marks`: نشان‌ها (`FAVORITE` | `COOK_LATER`) برای هر غذا
- `history`: غذاهای تاییدشده
- `user_prefs`: خواسته‌های ثبت‌شده (`type` = `WANT` | `AVOID` | `ALLERGY` | `DIET`، و `value`)

| `DessertRecipes.kt` | ۵۰ | کیک، شیرینی، بستنی، پودینگ |

### آپدیت‌ها (آینده)
1. نسخه‌ی اول: دیتابیس آماده داخل APK (`assets/recipes.db`) و بارگذاری با `createFromAsset`.
2. آپدیت‌های بعدی: فایل JSON روی سرور با شماره‌ی نسخه. اپ هنگام باز شدن فقط نسخه را چک می‌کند و در صورت جدید بودن، تفاوت را در Room ادغام می‌کند.
3. غذاهای کاربر (`source=user`) هرگز پاک یا بازنویسی نمی‌شوند.

## ۶. امنیت و محدودسازی دستگاه‌ها
اپ ──(Device ID + کد دعوت)──► سرور واسط ──► Gemini / Grok

- اپ در اولین اجرا یک UUID می‌سازد و با هر درخواست می‌فرستد.
- سرور یک **Allowlist** دارد: دستگاه ناشناس بلاک می‌شود.
- سرور Rate Limit دارد و می‌تواند بین Gemini و Grok جابجا شود.
- API های Gemini و Grok برای IP ایران بسته‌اند؛ سرور واسط باید خارج از ایران باشد.
- فعلاً به سرویس‌های گوگل (Firebase / Play Integrity) وابسته نشده‌ایم.

## ۷. وضعیت فعلی پروژه

### ✅ انجام شده
- اسکلت پروژه، تم، ناوبری با انیمیشن
- Room + DataStore + KSP
- دیالوگ خوش‌آمد

## ۸. چطور ادامه بدهیم

1. پروژه را با **Android Studio** باز کنید و Gradle Sync بزنید.
2. در `data/api/ApiConfig.kt` آدرس سرور واسط را بگذارید.
3. ترتیب پیشنهادی کار:
   1. دیپلوی سرور واسط (کد آماده در `server/`؛ مراحل در `server/README.md`)
   2. ساخت `assets/recipes.db` برای بارگذاری اولیه
   3. آپدیت دیتابیس از سرور
   4. تکمیل فرم «غذای جدید» (Suggest و حذف)
   5. افزودن غذای دستی توسط کاربر
   6. طراحی نهایی، انیمیشن‌ها، فونت فارسی
   7. تست باتری (Battery Historian / Profiler)
4. هر قابلیت جدید را با شاخه‌ی جدا (branch) توسعه دهید.
